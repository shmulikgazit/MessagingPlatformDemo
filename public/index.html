Agent routing (rings)

The pills at the top right show live status only — they are not buttons. Use the rows below to change availability and subscribe to rings.

Typical flow: connect → set availability (often ONLINE) → Subscribe routing tasks → accept or reject rings here or via events. Ring acceptance adds you as ASSIGNED_AGENT.

Step 1 — Availability (setAgentState)

Each button calls the same API as connection.setAgentState. Until you click one, availability is null on this connection. After a click, check the top-right Availability pill or the Connection status JSON — and the Live events log on the right for a line like agent/availability → AWAY.

Step 2 — Routing subscription

Separate from availability: this registers for routing-task / ring notifications so pending rings appear in the list below. The demo server also calls createRoutingTaskSubscription once right after a successful connect; use the button if you need another subscription (e.g. after a failed subscribe) or for testing.
